# Qonaq — архитектура и функционал MVP

Дата: 2026-11-26. Дедлайн хакатона: 2026-11-27, 23:00.

## Зачем

Сельский хозяин в Казахстане говорит только по-казахски и по-русски, а турист — только на своём языке.
Qonaq снимает языковой барьер на всём пути: страница дома за 60 секунд голосом, заявка туриста на его языке,
ответ хозяина кнопками, дорога без связи. Без комиссии, без сайта у хозяина, через WhatsApp, который у всех уже есть.

Цель на завтра: MVP, который жюри проходит само за минуту и «чувствует» продукт.
Цель после хакатона: реальный запуск в Саты. Поэтому фундамент (данные, роуты, безопасность ссылок) делаем
как для продакшена, а то, что нужно только для запуска (вход по SMS, модерация), откладываем.

## Цели, не-цели, анти-цели

Цели:
- Хозяин голосом или текстом создаёт страницу, ИИ делает карточку на 4 языках (kk, ru, en, zh) за ~15 секунд.
- Турист видит страницу на своём языке и цену в своей валюте, пишет вопрос на своём языке.
- Заявка приходит хозяину в WhatsApp по-русски, он отвечает кнопками, турист видит ответ на своём языке.
- Страница дома и карточка «Покажите водителю» открываются без интернета после первого визита.
- Демо для жюри работает на их телефонах: голос → QR → китайская страница → WhatsApp по-русски.

Не-цели (после хакатона):
- Вход по SMS/OTP, личные кабинеты, восстановление доступа.
- Онлайн-оплата, депозиты, комиссии.
- Отправка уведомлений через WhatsApp Business API (пока турист сам отправляет готовое сообщение через wa.me).
- Отзывы, рейтинги, модерация, админка.

Анти-цели (провал, даже если «работает»):
- Демо зависит от удачи: долгий ИИ, падение без интернета, ошибка на сцене.
- Хозяину нужно что-то читать на английском или регистрироваться.
- Турист видит русский текст, который не понимает.
- Любой, кто узнал код заявки, может ответить за хозяина.

## Подход (решение принято)

Рассмотрены три варианта:
1. **Next.js full-stack + SQLite/libSQL + Claude API** — выбран. Один проект, один деплой, серверные роуты
   для ИИ, та же база локально (файл) и в продакшене (Turso). Быстрее всего довести до красивого демо.
2. Отдельный бэкенд (FastAPI/Django) + SPA — два деплоя, вдвое больше склейки, на сутки это лишний риск.
3. Статический сайт + только wa.me ссылки, без базы — не даёт страницу заявки, ответ хозяина и живой экран для жюри.

## Стек

| Слой | Выбор | Почему |
| --- | --- | --- |
| Фронт + бэк | Next.js (App Router), TypeScript | один проект, серверные роуты, SSR для быстрых страниц |
| Стили | Tailwind CSS | быстро, мобильно |
| База | SQLite через libSQL + Drizzle ORM | локально файл, в проде Turso без смены кода |
| ИИ | Claude API (`@anthropic-ai/sdk`), модель Haiku 5.5 по умолчанию | скорость ~секунды, структурированный JSON |
| Голос | Web Speech API в браузере (kk-KZ, ru-RU) + ввод текстом | без лишних ключей; текст — запасной путь |
| Фото | сжатие в браузере до ~200 КБ, хранение в базе, отдача через `/api/photo/[id]` | без отдельного хранилища на MVP |
| QR | пакет `qrcode` | SVG/PNG, для экрана и плаката |
| Офлайн | Service Worker (PWA) | кэш страницы дома, фото, карточки водителя |
| «Реалтайм» | опрос сервера раз в 3 сек | надёжно на любом хостинге |
| Деплой | Vercel + Turso | бесплатно, публичная ссылка для QR жюри |

Нужно от вас: ключ `ANTHROPIC_API_KEY` (вставите в `.env.local` сами), аккаунты Vercel и Turso для деплоя.

## Языки и валюты

- Интерфейс: казахский, русский, английский, китайский. Язык туриста — из браузера (`Accept-Language`),
  переключатель в шапке. Хозяин по умолчанию видит русский, может переключить на казахский.
- Контент карточки переводится один раз при создании и хранится по языкам. Вопрос туриста и ответ хозяина
  переводятся при отправке.
- Цена хранится в тенге, туристу показывается в его валюте (CNY, USD, EUR, RUB) по фиксированному курсу с датой.

## Модель данных

**Listing (дом)**
- id, slug (`erlan`), village (`saty`), hostName, whatsapp (E.164), sourceLang, status (draft/published)
- rooms, priceKzt, priceGuests, breakfastIncluded, checkIn, extras: [{key, priceKzt}], lat/lng
- content: {kk, ru, en, zh} → title, description, extras[], rules, driverAddress
- photos: [photoId], editToken (секрет хозяина), isDemo, createdAt

**Request (заявка)**
- id, code (публичный, 6 символов), hostKey (секрет хозяина, 8 символов), listingId
- guestName, guestLang, guests, dateFrom, dateTo, nights, totalKzt
- status: new / available / busy
- createdAt

**Message (сообщение в заявке)**
- id, requestId, author (guest/host), lang, original, translations {kk, ru, en, zh}, action (available/busy/car/null), createdAt

**Photo**: id, listingId, mime, data, createdAt.

**Event** (для живого экрана): id, type, payload, createdAt.

## Безопасность ссылок

- Турист открывает `/r/{code}` — видит только свою заявку, отвечать за хозяина не может.
- Хозяин получает `/r/{code}?k={hostKey}` в WhatsApp — только с ключом видны кнопки ответа.
- Редактирование дома — по ссылке с `editToken`, токен сохраняется в cookie на телефоне хозяина.
- Коды из алфавита без похожих символов, ключи — криптостойкие случайные.
- Лимиты: не больше N заявок с одного IP в минуту, размер фото и текста ограничен.

## Экраны и функции

### Хозяин (интерфейс на русском или казахском)

1. **Главная `/`** — что такое Qonaq одним экраном, две кнопки: «Я хозяин — создать страницу» и «Я турист — найти жильё».
2. **Создание `/new`**
   - Большая кнопка микрофона, язык kk/ru, живая расшифровка на экране. Поле текста как запасной путь.
   - До 6 фото, сжатие в браузере, превью.
   - Номер WhatsApp, село (по умолчанию Саты, можно любое — для демо «Боровое»).
   - «Создать» → ИИ разбирает речь в карточку и переводит на 4 языка, прогресс «Понимаю… Перевожу…».
3. **Проверка карточки `/new/[id]`**
   - Поля, которые понял ИИ: название, комнаты, цена, что включено, доп. услуги, заезд, правила.
   - Правка любого поля касанием. Кнопка «Всё верно».
   - Превью: «Так вашу страницу увидит турист из Китая» (переключатель языков).
4. **Готово `/host/[id]`**
   - Ссылка `qonaq.kz/{village}/{slug}`, большой QR, кнопки «Поделиться в WhatsApp», «Скачать плакат».
   - Список заявок этого дома со статусами.
5. **Плакат `/poster/[id]`** — A4 для печати: фото, QR, «Отсканируйте» на 4 языках.
6. **Ответ на заявку `/r/[code]?k=…`**
   - Заявка по-русски: кто, откуда, даты, гостей, сумма по прайсу, вопрос (перевод + оригинал мелко).
   - Три большие кнопки: «Свободно», «Занято», «Машина есть, 8 000 ₸» (если машина есть в услугах).
   - Ответ голосом или текстом. Кнопка «Скопировать перевод» для вставки в WhatsApp.

### Турист (интерфейс на его языке)

7. **Каталог села `/[village]`** — например `/saty`: 4–5 домов, фото, цена в его валюте, расстояние до Кольсая.
8. **Страница дома `/[village]/[slug]`**
   - Фото, название, описание, услуги, заезд, правила — на его языке. Цена в его валюте и в тенге.
   - Форма: даты, количество гостей, имя, вопрос на родном языке. Итог по прайсу.
   - «Написать хозяину» → создаётся заявка, открывается WhatsApp с готовым русским сообщением
     и ссылкой для ответа, а сам турист попадает на страницу заявки.
   - Значок «Сохранено для офлайна».
9. **Страница заявки `/r/[code]`** — статус и ответы хозяина на языке туриста, обновляется сама.
   Работает и без WhatsApp: можно отправить заявку прямо из сайта.
10. **«Покажите водителю» `/[village]/[slug]/driver`** — на весь экран, крупно по-казахски и по-русски:
    куда ехать, телефон хозяина, точка на карте (ссылка в 2GIS/Google Maps). Работает офлайн.

### Для жюри

11. **Живой экран `/live`** — для проектора: большой QR на каталог, лента событий в реальном времени:
    «Создана страница: дом в Боровом», «Заявка из Китая: 你好… → Здравствуйте…», «Хозяин ответил: Свободно».
    Видно, как текст на одном языке превращается в другой.

## Как работает ИИ

- `POST /api/listings/draft`: текст (расшифровка или ввод) + язык → Claude возвращает строгий JSON
  (поля карточки + переводы на 4 языка). Если ИИ не уверен в поле — оставляет пустым, хозяин дополнит.
- `POST /api/requests`: вопрос туриста → перевод на русский и казахский, сборка сообщения для WhatsApp.
- `POST /api/requests/[code]/reply`: кнопка или текст хозяина → перевод на язык туриста.
- Таймаут и повтор при сбое; при ошибке хозяин видит понятное сообщение и может заполнить поля вручную.
- Ключ только на сервере, в браузер не уходит.

## Офлайн

- Service Worker кэширует страницу дома, её фото, карточку водителя и статику при первом открытии.
- Без сети показываются сохранённые версии, вверху пометка «Нет сети — показана сохранённая версия».

## Данные для демо

- Каталог Саты: 5 домов, все выдуманные и помечены как пример (`isDemo`), пока нет реальных хозяев.
  Фото — заглушки-иллюстрации, заменим на настоящие, когда будут.
- Сценарий жюри: судья наговаривает «У меня дом в Боровом, 3 комнаты, 20 тысяч…» → QR на экране →
  второй судья сканирует, видит страницу по-китайски, отправляет заявку → WhatsApp по-русски → ответ кнопкой.

## Приоритеты на сутки

- P0: создание голосом/текстом → карточка → публикация; страница дома на 4 языках с валютой; заявка → WhatsApp;
  страница заявки с кнопками хозяина и ответом у туриста; QR; каталог Саты; карточка водителя офлайн.
- P1: живой экран `/live`, плакат A4, список заявок у хозяина, ответ хозяина голосом.
- P2 (после хакатона): вход по SMS, WhatsApp Business API, модерация, отзывы, оплата, аналитика.

## Как работаем

- Я собираю фундамент: проект, база, типы, контракты API, переводы интерфейса.
- Затем параллельно работают агенты на непересекающихся файлах: экраны хозяина, экраны туриста,
  ИИ и API, офлайн. После них — ревью кода, тесты, проверка в браузере, репетиция демо.

## Решения, принятые мной (можно поменять)

- Next.js + SQLite/Turso + Claude Haiku 5.5, деплой на Vercel.
- Голос через браузер, без отдельного сервиса распознавания.
- Фото в базе, а не в облачном хранилище.
- Без входа: доступ хозяина по секретной ссылке.
- Опрос раз в 3 секунды вместо WebSocket.
